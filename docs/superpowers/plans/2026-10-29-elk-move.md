# ELK moves to the ops cluster: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the lab's logs are stored, searched and backed up on hetops-3 instead of the lab server, with Kibana reachable through hetops-3's own Cloudflare tunnel.

**Architecture:** ECK on the ops cluster runs Elasticsearch `ops-logs` and Kibana `ops-kibana` in namespace `logging` (Argo app `logging`, `clusters/ops/logging/`). Elasticsearch listens on the Tailscale address only (hostPort 9200 on 100.89.67.82) with a TLS certificate from a CA kept in git. A second Filebeat on the lab, `ops-filebeat`, ships there with a file-realm user that can only write. Setup (retention, templates, snapshot repositories and policies) and Kibana's setup (one data view, three detection rules) are JSON in git, applied by Argo PostSync Jobs.

**Tech Stack:** ECK operator 3.5.0, Elasticsearch / Kibana / Filebeat 9.5.5, local-path-provisioner v0.0.30, cloudflared 2026.10.0, Gatus v5.37.0, Bedrock (Ansible), Argo CD, sealed-secrets, Tailscale policy as code.

**Spec:** [2026-10-29-elk-move-design.md](../specs/2026-10-29-elk-move-design.md). Three design changes made while planning are in its Addendum 1 (Task 1 adds it): file-realm users instead of an API key made by a Job; a CA in git instead of ECK's self-signed one; a Gatus freshness check instead of a Filebeat alert in the lab's Prometheus.

```markdown
## Addendum 1, 29 Oct: three choices made while planning

- **File-realm users, not an API key made by a Job.** ECK reads users and roles from Secrets (`spec.auth.fileRealm`, `spec.auth.roles`), so the shipper's and the watcher's identities are declared in git like everything else, with no imperative step and nothing to recreate after a rebuild. - **A CA in git, not ECK's self-signed certificate.** ECK's self-signed CA is regenerated on a rebuild and every client would need its new certificate. - **Freshness in Gatus instead of a Filebeat alert in the lab's Prometheus.** Filebeat's metrics are not in Prometheus format, so the alert would need an exporter on the lab. A Gatus check that counts `logs-lab-default` documents from the last 10 minutes proves the whole path (lab Filebeat, Tailscale, Elasticsearch) with nothing new on the lab.
- **Storage on hetops-3.** It has no storage provisioner; `local-path-provisioner` v0.0.30 (the lab's version) is installed through Argo from git.
```
